# UX and accessibility audit — 2026-11-10

Full audit of `Frontend/` against the project rubric: [`docs/ux.md`](../ux.md)
(principles, ten Nielsen heuristics, dark patterns) and
[`docs/accessibility.md`](../accessibility.md) (POUR, WCAG 2.1 AA criteria,
assistive-technology procedure). No code was changed by this session; the only
writes are this file, its screenshots, the two `Status` tables and the
changelog entry.

## 1. Method, environment, what was executed

**Date** 2026-11-10. **Commit** `7263cf2` (`andrea-frontend`), working tree not
clean: `Frontend/src/app/(tabs)/agreements.jsx` modified and `docs/*` in
progress before the session started. Findings cite the tree as it was read.

**Rubric read before the review**: `docs/ux.md`, `docs/accessibility.md`,
`docs/frontend.md`, `docs/overview.md`, `docs/decisions.md` (so that decided
choices are not reported as defects), `docs/backend-gaps.md`.

**Orchestration.** Four read-only subagent lanes in parallel (the concurrency
limit of the session), plus two areas audited directly by the parent, which is
also the only one that opened the browser — no lane was allowed to write, run
git or touch Playwright:

| Lane | Scope | Output |
| --- | --- | --- |
| 1 scout | routes, screens, components, hooks, where the four states live, tokens, nav, session expiry | index (used to seed lanes 2-4) |
| 2 reviewer | Nielsen L1-L5, L10, six principles | 20 candidate findings |
| 3 reviewer | Nielsen L6-L9, dark patterns, Italian copy | 20 candidate findings |
| 4 reviewer | static WCAG AA: roles, labels, states, targets, contrast, focus, `lang`, live regions | 23 candidate findings, contrasts recomputed |
| 5 parent (no subagent) | design system: tokens, typography, spacing, hierarchy, light/dark, motion, cross-screen consistency | 5 findings |
| 6 parent (no subagent) | platform conventions, perceived performance, tap cost | 3 findings |

Every candidate was then re-checked by the parent: the cited file and line were
reopened, the claim kept only if the evidence held, dimensions merged when the
root cause was the same, and the live browser pass used to confirm or downgrade
the interaction claims. Three candidate findings were dropped this way — two
contradicted by the browser, one optional in WCAG terms — one was moved to §7
because its state could not be produced, and three severities were lowered.

**Evidence status used in every row**: `VERIFIED` — read in the file or executed
in the browser; `DEDUCED` — inferred from code without executing it (never above
severity 2); `NOT VERIFIABLE` — needs a state or a datum that does not exist
(§7, never a finding).

**Live environment (started by this session, see §8).** Docker Desktop,
`Backend/compose.yaml` stack on port 8000 (MySQL 8.0 + PHP dev server), and
`cd Frontend && npx expo start --web` on port 8081. Logins verified before the
browser was opened:

```text
POST /api/auth/login {"username":"mario.rossi","password":"demo"}   -> 200, ROLE_USER
POST /api/auth/login {"username":"staff.anna","password":"demo"}    -> 200, ROLE_USER + ROLE_STAFF
```

No demo row was modified and no throwaway account was created (the demo
credentials worked, and the only destructive paths were exercised up to the
confirmation and then cancelled).

**Executed live** (Chromium through Playwright, viewports 390×844 and 1440×900,
themes light and dark): login, home with catalog (20 rows + "Carica altri"),
filter bar, service detail modal, proposals, match, offer-and-request,
agreements with the bell panel, profile, theme switch, edit-profile, report
screen, staff reports, staff users, the confirm modal, the web nav menu, the
401 paths, the 200 % reflow measurement, the keyboard walk and the
live-region/accessible-name inspection of the DOM.

**Not executed live**: VoiceOver and TalkBack (no physical device in this
session), reduced motion on a device (only the web media query path),
`lang` on the *exported* web build (only the dev server was served), the
session-expiry banner (a valid token with less than 5 minutes left cannot be
produced without the backend key), and the iOS dynamic-type behaviour. See §7.

**Environment caveat, not a finding.** The PHP dev server answers in 2-5 s per
request and serialises under a burst; several app requests crossed the client's
10 s timeout during the session and produced the timeout state. That is a
property of `php -S` with a Windows bind mount, not of the app, so it is not
scored — but it is why the timeout state appears in screenshots 02, 09 and 18.

## 2. Scores

Counted per dimension, one finding = one root cause. Formula from the brief:
`10 − (0.2·n1 + 0.5·n2 + 1.5·n3 + 3·n4)`, floor 0, dimension capped at 5 when it
holds a severity-4 finding.

| Dimension | Weight | sev1 | sev2 | sev3 | sev4 | Raw | Score | Weighted |
| --- | --- | --- | --- | --- | --- | --- | --- | --- |
| Usability (heuristics + six principles) | 30 % | 1 | 9 | 3 | 0 | −9.2 | 0.8 | 0.24 |
| Accessibility (WCAG 2.1 AA, app) | 25 % | 1 | 8 | 2 | 0 | −7.2 | 2.8 | 0.70 |
| States and copy | 15 % | 4 | 4 | 2 | 1 | −8.8 | 1.2 | 0.18 |
| Design system and visual coherence | 15 % | 2 | 3 | 0 | 0 | −1.9 | 8.1 | 1.22 |
| Platform and perceived responsiveness | 15 % | 0 | 3 | 0 | 0 | −1.5 | 8.5 | 1.28 |
| **Total** | 100 % | **8** | **27** | **7** | **1** | | | **3.6** |

**Final score: 3.6 / 10.** Findings: 43 (8 severity 1, 27 severity 2, 7
severity 3, 1 severity 4).

Read the number for what it is. The formula is linear in the *count* of
findings, so a first full pass over twelve screens and thirty-four components
lands low by construction: a dimension with nine severity-2 findings already
scores 5.5, and ten of them score 5. The 3.6 says "this build cannot be declared
WCAG AA and has one broken flow", not "the app is unusable": several findings
are one-line fixes, and the design-system dimension (8.1) shows what the code
looks like where a rule was actually enforced end to end. The single severity-4
finding is the session-expiry dead end (F31), which alone caps "states and copy"
at 1.2.

Severity rule applied (stated so the count can be redone): severity 3 when a
user loses information or operability, or an irreversible action has no guard;
severity 2 when the rubric or a WCAG AA criterion is not met but everything
stays reachable through a workaround; severity 1 when the defect is cosmetic or
a wording/scale inconsistency.

## 6. Method notes worth keeping

- **200 % text** was measured by halving the CSS viewport (195×422) with the
  device scale at 2: no horizontal overflow (`scrollWidth == innerWidth`), no
  overlap, and every text container reflowed — the only clipping found was
  `numberOfLines={2}` on the card title, which is content-available in the
  detail panel and therefore not a finding. The native dynamic-type case is a
  different mechanism and could not be exercised (§7).
- **Session expiry** was provoked twice without touching the backend TTL: a
  forged token in `localStorage` (`barattolo.token`), and `page.route`
  answering 401 to every authenticated call. Both produce the same behaviour;
  the second is the one that shows the real backend string.
- **Contrast** was recomputed from the token hex values with the WCAG 2.x
  relative-luminance formula, not read from the comments: `borderInput`
  reproduces (3.62/3.36 light, 3.35/3.77 dark) and exactly one pair fails.
- **Tap counts** come from the code paths, not from the live app, because the
  environment's latency would have made timings meaningless.
